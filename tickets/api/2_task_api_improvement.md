# Ticket: Add DTO Validation for Task APIs

## Objective

Add DTOs and request validation to the existing Task CRUD APIs.

The backend must validate incoming data before passing it to `TaskService`.

For this ticket:

- Keep the existing `Task` interface.
- Use DTOs for `POST` and `PATCH` request bodies.
- Enable NestJS global validation.
- Do not refactor the shared contract yet.
- Do not add a database.

The following packages will be installed before implementation:

```bash
pnpm add class-validator class-transformer
```

---

## 1. Enable Global ValidationPipe

Update the NestJS bootstrap file, usually:

```text
main.ts
```

Import `ValidationPipe`:

```ts
import { ValidationPipe } from "@nestjs/common";
```

Then enable it globally:

```ts
async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,
      forbidNonWhitelisted: true,
      transform: true,
    }),
  );
}
```

Configuration:

#### `whitelist: true`

Only properties defined in the DTO are accepted.

#### `forbidNonWhitelisted: true`

If the request contains an unknown property, return `400 Bad Request`.

Example:

```json
{
  "title": "Build Task APIs",
  "completed": false,
  "admin": true
}
```

`admin` is not defined in the DTO, so the request must be rejected.

#### `transform: true`

Allow NestJS to transform incoming request data based on the DTO when needed.

## 3. Create `CreateTaskDto`

Create:

```text
dto/create-task.dto.ts
```

The API should allow the client to provide:

- `title`
- `description`
- `completed`

The client must not provide:

- `id`
- `createdAt`
- `updatedAt`

These fields are generated by the backend.

Example:

```ts
import { IsBoolean, IsOptional, IsString, MaxLength, MinLength } from "class-validator";
import type { CreateTaskInput } from "../task.interface";

export class CreateTaskDto implements CreateTaskInput {
  @IsString()
  @MinLength(1)
  @MaxLength(200)
  title!: string;

  @IsOptional()
  @IsString()
  @MaxLength(1000)
  description?: string;

  @IsBoolean()
  completed: boolean;
}
```

Validation rules:

### `title`

- Required.
- Must be a string.
- Must not be empty.
- Maximum 200 characters.

### `description`

- Optional.
- Must be a string when provided.
- Maximum 1000 characters.

### `completed`

- Required.
- Must be a boolean.

## 4. Create `UpdateTaskDto`

Create:

```text
dto/update-task.dto.ts
```

For this ticket, define the DTO directly instead of adding another package.

All fields are optional because `PATCH` only updates provided fields.

```ts
import { IsBoolean, IsOptional, IsString, MaxLength, MinLength } from "class-validator";
import type { UpdateTaskInput } from "../task.interface";

export class UpdateTaskDto implements UpdateTaskInput {
  @IsOptional()
  @IsString()
  @MinLength(1)
  @MaxLength(200)
  title?: string;

  @IsOptional()
  @IsString()
  @MaxLength(1000)
  description?: string;

  @IsOptional()
  @IsBoolean()
  completed?: boolean;
}
```

The client must not be able to update:

- `id`
- `createdAt`
- `updatedAt`

`updatedAt` must continue to be generated by the backend when a Task is updated.

## 5. Update `TaskController`

Replace the current request body types with DTOs.

Before:

```ts
@Post()
create(@Body() task: Task) {
  return this.taskService.create(task);
}
```

Change to:

```ts
@Post()
create(@Body() dto: CreateTaskDto) {
  return this.taskService.create(dto);
}
```

For update:

```ts
@Patch(':id')
update(
  @Param('id') id: string,
  @Body() dto: UpdateTaskDto,
) {
  return this.taskService.update(id, dto);
}
```

Import:

```ts
import { CreateTaskDto } from "./dto/create-task.dto";
import { UpdateTaskDto } from "./dto/update-task.dto";
```

DTOs should be used only for request input.

The existing `Task` interface can still be used for API response and stored Task data.

---

## 6. Update `TaskService`

Update the service method parameters to use DTOs.

Before:

```ts
create(task: Task): Task
```

Change to:

```ts
create(dto: CreateTaskDto): Task
```

Example:

```ts
create(dto: CreateTaskDto): Task {
  const now = new Date().toISOString();

  const task: Task = {
    id: crypto.randomUUID(),
    ...dto,
    createdAt: now,
    updatedAt: now,
  };

  this.tasks.push(task);

  return task;
}
```

Update should also receive `UpdateTaskDto`:

```ts
update(id: string, dto: UpdateTaskDto): Task
```

Example:

```ts
update(id: string, dto: UpdateTaskDto): Task {
  const task = this.tasks.find((item) => item.id === id);

  if (!task) {
    throw new NotFoundException(`Task ${id} not found`);
  }

  Object.assign(task, dto, {
    updatedAt: new Date().toISOString(),
  });

  return task;
}
```

Keep the in-memory data typed as:

```ts
private tasks: Task[] = [];
```

Do not replace `Task` with DTO for stored data.

The responsibilities should be:

```text
CreateTaskDto
    ↓
Validate POST input
    ↓
TaskService
    ↓
Task

UpdateTaskDto
    ↓
Validate PATCH input
    ↓
TaskService
    ↓
Task
```

## 7. Verify Validation with Postman

### Valid Create Request

```http
POST /tasks
```

```json
{
  "title": "Build Task APIs",
  "description": "Implement Task API validation",
  "completed": false
}
```

Expected:

```text
201 Created
```

---

### Invalid `title`

```json
{
  "title": "",
  "completed": false
}
```

Expected:

```text
400 Bad Request
```

---

### Invalid `completed`

```json
{
  "title": "Build Task APIs",
  "completed": "false"
}
```

Expected:

```text
400 Bad Request
```

The backend must not accept a string as a boolean.

---

### Unknown Property

```json
{
  "title": "Build Task APIs",
  "completed": false,
  "admin": true
}
```

Expected:

```text
400 Bad Request
```

---

### Attempt to Set Backend Fields

```json
{
  "title": "Build Task APIs",
  "completed": false,
  "id": "custom-id",
  "createdAt": "2020-01-01",
  "updatedAt": "2020-01-01"
}
```

Expected:

```text
400 Bad Request
```

The client must not control these fields.

---

### Valid Partial Update

```http
PATCH /tasks/:id
```

```json
{
  "completed": true
}
```

Expected:

- Task is updated.
- Existing `id` is unchanged.
- Existing `createdAt` is unchanged.
- `updatedAt` is updated.

---

### Invalid Update

```json
{
  "completed": "yes"
}
```

Expected:

```text
400 Bad Request
```

## Acceptance Criteria

- `class-validator` and `class-transformer` are used for request validation.
- Global `ValidationPipe` is enabled.
- `whitelist` is enabled.
- Unknown request fields are rejected.
- `CreateTaskDto` is created.
- `UpdateTaskDto` is created.
- `POST /tasks` uses `CreateTaskDto`.
- `PATCH /tasks/:id` uses `UpdateTaskDto`.
- `TaskService.create()` accepts `CreateTaskDto`.
- `TaskService.update()` accepts `UpdateTaskDto`.
- The existing `Task` interface is still used for Task data and API responses.
- The client cannot provide or update `id`, `createdAt`, or `updatedAt`.
- Invalid input returns `400 Bad Request`.
- Existing CRUD APIs continue to work correctly.
- All validation cases can be verified using Postman.
